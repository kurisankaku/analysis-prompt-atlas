## 1. プロダクト定義

### 1.1 一行定義

> 数学・統計の知識がゼロでも、各データ分析手法が「**何が分かり・どんなデータが要り・いつ使うか**」を即座に腹落ちでき、結果として**自分の言葉でAIに分析を指示できるようになる**、目的起点の「手法理解カタログ」。

### 1.2 中核となる価値

- **発見**: 自分が知らなかった分析手法に出会える。
- **理解**: 専門用語・数式に頼らず、手法の意味が腹落ちする。
- **応用**: 理解できれば、ユーザーは**自分の言葉で**AIに分析を指示できる。

理解は「手段」、AIへの指示の幅を広げることが「目的」。この2つを両立させる。

### 1.3 中心となる体験

**カタログ閲覧・発見**が中心。インタラクティブな機能（プロンプト自動生成など）ではなく、**「説明の分かりやすさ・粒度の統一」そのもの**がプロダクトの価値。

### 1.4 やらないこと（YAGNI / 非対象）

- プロンプトの**自動生成**（本サービスはプロンプト生成ツールではない）
- データ分析の**代行・自動実行**
- 統計学・線形代数・微積分の厳密な教科書的解説、学術論文レベルの証明
- 特定プログラミング言語の実装コード集 / ライブラリのAPIリファレンス
- 特定BIツールの操作手順、特定企業・業界専用マニュアル
- アカウント・ログイン（v1では持たない）

### 1.5 数式の扱い

数式・理論は**主役にしない**。各手法を理解するために必要な範囲で、簡潔な式・概念説明を**補助情報**（折りたたみ表示など）として添える程度にとどめる。

## 2. 対象ユーザー

- AIにデータ分析を依頼したいが、統計・数学の専門家ではないユーザー
- 業務データ・ログ・売上・アンケートなどをAIで分析したいユーザー
- 分析手法の名前を知らないが、目的に合う分析方法を知りたいユーザー
- AIにより深い・多角的な分析をさせる観点を探しているユーザー
- 手法の比較・使い分けを知りたいユーザー

|---|---|---|

| 5 | **関係マップ（アトラス）** | 手法どうしのつながりをグラフ可視化。手法ページから「周辺を見る」で開く＋全体俯瞰 |
| 6 | **検索結果** | キーワードから 手法 / 目的 / データ種類 を横断ヒット |
| 7 | **共通注意ページ**（静的） | 「相関≠因果」など横断的な注意喚起 |

- **主役の入口は「目的から探す」**。トップで15の分析目的をカード提示する。

- **回遊動線**: 目的 → 手法群 → 手法詳細 →（関連手法 / 比較 / 関係マップ）で行き来する。
- 専門用語にはツールチップ的なミニ説明を添え、文脈内で理解を補う。

## 4. 手法詳細ページの構成（全手法で統一する固定テンプレート）

「ゼロ知識でも腹落ちさせる」ための工夫を標準搭載する。全手法でこの順序・構成を統一し、粒度をそろえる。

1. **ヘッダ**: 手法名 / 読み方 / 英語名 / 難易度バッジ / 性質タグ / 所属（目的・データ種類・カテゴリ）
2. **これは何?**: 一言説明 ＋ **日常のたとえ**
3. **何が分かる?**: 結果の意味（得られる示唆）
4. **どんなデータを用意する?**: 必要な入力データの形 ＋ **ミニ例表**（数行のサンプル表）
5. **サンプルで見る**: サンプルデータの分布・結果を **グラフ／チャート** で示す（役立つ場合）。例: 標準偏差は同じ平均でも散らばりが異なる2分布を並べる、相関係数は相関0.9と0.1の散布図を見せる
6. **どんな時に使う / 使わない方がいい時**: 向く目的・場面 / 不向きな場面
7. **結果の読み方**: 出力数値・図の解釈の**具体例**
8. **使う前 → 後（ビフォーアフター）**: この手法を使うと何が新たに見えるか
9. **注意点**: 誤解しやすい点・前提・落とし穴（手法固有の注意）
10. **関連手法（次に見る）**: 類似 / 比較 / 前提 / 発展 / 併用 / 前処理 / 後処理 / 代替 / 補完
11. *(補助)* **AIへの頼み方の一文例**
12. *(任意)* ごく簡潔な数式（折りたたみ表示・補助情報）

### 4.1 「理解の工夫」標準搭載要素（再掲）

- 日常のたとえ話（必須・各手法1つ）
- 入力データのミニ例（表）
- 結果の読み方の具体例
- 使う前 / 後のビフォーアフター
- グラフ・チャートによるサンプルデータ分布の可視化（役立つ場合）

## 5. データモデル

### 5.1 手法エンティティ（Method）

**必須項目**（要件§8.1 ＋ 本サービスの「理解の工夫」を追加）:

| 区分 | 項目 |
|---|---|
| 識別 | id / 手法名 / 読み方 / 英語名 |
| 理解の核 | 概要 / 一言説明 / **日常のたとえ** |
| 用途 | 主な用途（何が分かるか） / 向いている分析目的 |
| データ | 向いているデータ / **用意するデータ（入力の形）＋ミニ例表** / **サンプルデータ＋可視化指定** |
| 結果 | 得られる結果（結果の意味） / **結果の読み方の具体例** / **使う前→後（ビフォーアフター）** |
| 使い分け | 使うべき場面 / 使わない方がいい場面 |
| 注意 | 注意点 |
| つながり | 関連手法（関係タイプ付き） |
| 補助 | AIへの頼み方の一文例 |
| メタ | 難易度 / 性質タグ / キーワード / 所属（目的[] ・ データ種類[] ・ カテゴリ[]） |

**任意項目**（要件§8.2）: 前提条件 / 必要データ量 / 解釈のしやすさ / 計算コスト / 可視化との相性 / 似た手法との違い / 組み合わせやすい手法 / 誤用例 / 簡潔な数式。

### 5.2 分類体系（3軸・値は要件書準拠）

いずれの軸も**多対多**（1手法が複数の目的・データ種類・カテゴリに属しうる。例: PCA = 次元削減＆グループ分け、多次元データ、次元削減カテゴリ）。

- **分析目的（15）**: 傾向 / ばらつき / 関係性 / 影響要因 / 予測 / 分類 / グループ分け / 類似 / 異常 / 変化 / ランキング / 最適化 / 要約 / 次元削減 / 構造
- **データ種類（11）**: 数値 / カテゴリ / 時系列 / テキスト / 画像 / ログ / 売上・購買 / アンケート / 位置情報 / ネットワーク / 多次元
- **数学・統計カテゴリ（15）**: 基礎統計 / 確率・分布 / 検定 / 回帰 / 分類 / クラスタリング / 次元削減 / ベクトル・距離・類似度 / 行列 / 微積・最適化 / 時系列 / 異常検知 / ネットワーク / テキスト / ソート・ランキング

### 5.3 手法間の関係（9種・要件§14準拠）

| 関係 | 内容 | 方向性 |
|---|---|---|
| 類似 | 目的や使い方が近い | 無向 |
| 比較対象 | どちらを使うか比較されやすい | 無向 |
| 前提 | 理解・利用の前提となる | 有向（前提 → 本手法） |
| 発展 | より高度な応用手法 | 有向（本手法 → 発展） |
| 併用 | 一緒に使われやすい | 無向 |
| 前処理 | 対象手法の前に使われやすい | 有向（前処理 → 本手法） |
| 後処理 | 対象手法の後に使われやすい | 有向（本手法 → 後処理） |
| 代替 | 似た目的で代わりに使える | 無向 |
| 補完 | 弱点を補う関係にある | 無向 |

この関係データが **比較ビュー（§3.1 #4）** と **関係マップ／アトラス（§3.1 #5）** の土台になる。

### 5.4 難易度（要件§15準拠）

基礎 / 初級 / 中級 / 上級 / 高度。難易度フィルタ（§6）に利用する。

### 5.5 性質タグ（要件§16準拠）

基礎統計 / 可視化向き / 予測 / 分類 / 回帰 / クラスタリング / 異常検知 / 時系列 / テキスト分析 / 画像分析 / ネットワーク分析 / 類似度 / 距離 / ベクトル / 行列 / 最適化 / 検定 / 因果推論 / 説明可能性 / 大量データ向き / 少量データでも可 / 解釈しやすい / 解釈が難しい / 前処理向き / 後処理向き 等。

## 7. v1スコープと収録方針

### 7.1 収録方針: 段階拡張（質を先に担保）

- **フェーズ1**: 各カテゴリの代表 **約30〜40件** を **フル構成**（§4のテンプレート全項目）で完成させ、品質テンプレを確立する。基礎統計を厚めにし、初心者が最初に出会う手法を優先する。
- **フェーズ2**: **100件以上**へ拡張（要件§19の到達目標を満たす）。

### 7.2 フェーズ1 収録候補（代表手法・目安 約36件）

実装計画フェーズで最終確定するが、現時点の候補は以下。各分析目的カテゴリを最低1〜2件カバーし、基礎統計・可視化を厚くする。

- 基礎統計: 平均 / 中央値 / 最頻値 / 分散 / 標準偏差 / 四分位数・四分位範囲 / パーセンタイル / 相関係数
- 可視化: ヒストグラム / 箱ひげ図 / 散布図 / 折れ線グラフ / ヒートマップ
- 前処理: 標準化 / 正規化 / 欠損値処理 / 外れ値処理
- 検定: t検定 / カイ二乗検定 / ANOVA / A/Bテスト
- 回帰・予測: 単回帰分析 / 重回帰分析 / ロジスティック回帰 / 移動平均（時系列予測の入口）
- 分類: 決定木 / ランダムフォレスト / k近傍法 / 混同行列（Precision・Recall・F1）
- クラスタリング: k-means / 階層クラスタリング / DBSCAN
- 異常検知: z-score / IQR
- 次元削減: PCA
- ベクトル・類似度: コサイン類似度 / ユークリッド距離

### 7.3 v1機能セット

- 目的起点トップ（主入口）＋ 3軸ハブ（目的・データ種類・カテゴリ）

### 7.5 将来拡張（v1非対象）

## 8. コンテンツ品質基準（要件§20準拠）

- 非専門家にも理解しやすい表現であること
- 手法名だけでなく**用途**が分かること
- AIに依頼する際の具体的な指示に**変換しやすい**こと（ユーザーが自分の言葉で）
- 手法の**過信を避ける注意点**が含まれること
- 関連手法により**次の探索**ができること
- 同じ目的に使える複数手法を**比較**できること
- データ種類と分析目的の**両方**から手法を理解できること
- 数式は必要最低限にし、説明の補助として扱うこと
- 専門用語には簡潔な説明を付けること
- 初心者向け説明と発展的説明を混同しないこと

## 10. 要件書からの意図的な差分（合意済み）

ユーザーとの合意のうえで、元要件から意図的にズラした点が2つある。

### 【差分1】プロンプト生成を主役にしない

要件§13は9種類のAIプロンプト例を扱うことを求めるが、本サービスは「プロンプト生成サイトにしない」というユーザーの明確な意図に従う。

- **対応**: 各手法に「AIへの頼み方の一文例」を**補助**として添え、目的ハブに「広く提案させる探索型プロンプト」例を掲載する。これにより「複数の依頼観点を示す」という受け入れ条件の趣旨は満たしつつ、**生成機能は持たない**。
- **狙い**: 主役はあくまで「手法の理解」。理解できればユーザーが自分の言葉で指示できる、という価値設計。

### 【差分2】v1初期は100件未満から始める

要件§19の「初期100件以上」は**最終到達目標として保持**しつつ、品質を先に担保するため段階拡張する。

- **対応**: v1フェーズ1は30〜40件をフル構成で完成、フェーズ2で100件以上に到達。
- **狙い**: 本プロダクトの価値は「説明の質」そのものであり、量を急いで質を落とすと価値が損なわれるため。

## 11. 用語

- **手法エンティティ / Method**: 1つの分析手法・統計手法・数学的概念を表すデータ単位。
- **分類軸**: 手法を探すための切り口。目的 / データ種類 / 数学・統計カテゴリ の3軸。
- **関係マップ / アトラス**: 手法どうしの関係（§5.3）をグラフとして可視化したビュー。
- **フル構成**: §4のテンプレート全項目を満たした手法詳細ページ。
